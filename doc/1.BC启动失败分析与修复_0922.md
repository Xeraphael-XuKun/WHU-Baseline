# B/C 启动失败分析与修复

> 日期：2026-09-22

## 1. 结论

B、C 是同一个配置接入错误，不是显存不足，也不是 `K=4/192` 或
`K=2/96` 本身不可运行。

两组任务均已完成以下步骤：

- 读取 WHU-MARS；
- 构建 `StratifiedPKMViewSampler`；
- 验证 batch contract；
- 构建 CLIP ViT-B/16 并加载预训练参数。

随后在 `loss/make_loss.py` 构建 loss 时失败：

```text
ValueError: expected PKM sampler, but got PKM_VIEW
```

根因是 loss 工厂仍把 sampler 名称硬编码为只允许 `PKM`。`PKM_VIEW`
改变的是 PID/视角抽样方式，输出仍是相同的 P×K 身份 batch，CE 和
batch-hard triplet 的输入接口没有变化，因此应允许两种 sampler 共用同一
baseline loss。

## 2. 修复

`loss/make_loss.py` 的允许集合改为：

```python
('PKM', 'PKM_VIEW')
```

没有修改 loss 公式、权重、模型结构、优化器或 A 的原始 `PKMSampler`。

`tools/audit_candidates.py` 现在除 sampler/batch 审计外，还会对 A、B、C
实际调用 `make_loss`。服务器预检必须同时出现：

```text
A_baseline_candidate.yml: LOSS_CONSTRUCTION_OK
B_baseline_candidate.yml: LOSS_CONSTRUCTION_OK
C_fused_baseline_candidate.yml: LOSS_CONSTRUCTION_OK
CANDIDATE_AUDIT_OK
PREFLIGHT_OK
```

## 5. 证据边界

- 服务器预检通过后，仍需以 B/C 出现首个正常训练 iteration 作为运行时接受标准。
