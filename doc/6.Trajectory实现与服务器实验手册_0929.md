# 6. Trajectory实现与服务器实验手册（2026-09-29）

## 本轮目标与方法定义

核心比较为 A 与 A + Trajectory，损失仍只有 CE + pre-BN soft-margin batch-hard Triplet。
没有 VTC、文本锚点、第二次视觉前向、aerial-only gate 或额外视角监督。
idea PDF 物理第 8–10 页提供公式与参考代码；其历史分数不能作为当前 A 上的新实验结果。

对第 l 个 block，先注入历史修正，再用其真实输入计算 V_l = output_l - input_l。
第 0 层无修正，第 1 层只有速度，从第 2 层起 D = V_prev + beta*(V_prev - V_prev_prev)。
beta 固定 1，方向按最后一个 channel 维做 FP32、无可学习仿射参数的 LayerNorm。
gain 覆盖 CLS 与所有 patch，形状 [11,1,129,768]，新增 1,089,792 个参数。
全部视角、模态共享 gain；历史仅存在于一次前向，不跨 batch 缓存，不 detach 速度。

注入前后的算术、token 顺序、CLIP 权重映射不变。关闭 ENABLED 时不创建任何新增参数；
trajectory_gate=0 绕过修正，供机制验证使用。正式训练与 query/gallery 推理均固定 gate=1。

## 主方案与补充方案的选择

主方案有效 G = s*tanh(g/s)，s=0.1，原始 g 零初始化。
每个 token-channel 的有效系数被限制在 [-0.1,0.1]，但这不等于整个特征变化被限制在 0.1。
选择理由是速度/加速度可能含背景噪声，限制稠密系数可控制后续修正放大；零点 dG/dg=1，
保持与直接 gain 相同的起步梯度尺度，避免 0.1*tanh(g) 将起步学习速度缩小十倍。
饱和也可能损失必要的修正能力，因此保留 G=g 的直接 gain 对照。
0.1 是首轮工程假设，尚无效果证据；不会根据测试集最佳 checkpoint 偷换正式结果。

PDF 正文提到有界化，但参考代码使用直接 gain；主方案是在用户授权下明确补全的设计选择。
完整梯度传播遵循参考代码，beta=1 遵循公式；本轮先不扩展 detach、beta 等额外消融。
checkpoint 保存 beta/bound 语义缓冲区，加载时拒绝方法开关或 beta/bound 不匹配，
避免拿主方案配置评测直接 gain 权重。两者均从相同 CLIP 初始化开始，不从历史 A epoch-60 续训。
