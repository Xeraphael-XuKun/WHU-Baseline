# 9. Trajectory full 商汤单卡 A800 实验手册

## 1. 目标与实验矩阵

在当前 A baseline 与商汤 `whu_mars` 环境中，补充参考 RGB 四格 VTC。配置、脚本及输出名称统一使用 **full**；full 的方法含义仍明确为 Trajectory + 参考 VTC。

| 实验 | 配置 | gain | 直接对照 |
|---|---|---|---|
| direct full | `configs/A_trajectory_direct_full.yml` | 原始可学习 gain，无界 | 已完成的 A + direct Trajectory |
| bounded full | `configs/A_trajectory_full.yml` | `0.1*tanh(raw_gain/0.1)` | 已完成的 A + bounded Trajectory |

每组单独前台训练60 epoch，随后自动串联 **post-BN 独立复评 → pre-BN 独立复评**，均加载该组同一个 `transformer_60.pth`。训练内每10 epoch仍使用pre-BN，正式主比较用post、pre作补充，不按结果逐行挑选读出。

## 2. 实现与参考保持一致的部分

- 主前向处理RGB/IR/Thermal全部192张图片，CE作用于post-BN分类结果，soft-margin batch-hard Triplet作用于pre-BN 768维特征。
- 仅取其中64张RGB图像进行第二次before前向，关闭Trajectory，**不detach**；before分支不经过BN，不重复更新BN running stats。
- after复用主前向RGB特征，不多做第三次视觉前向；推理只运行一次gate=1，不执行文本或before分支。
- 两个文本锚点由冻结CLIP文本塔与可学习prompt生成；2个视角向量加4个共享上下文向量，共3072个可学习prompt参数。所谓5个slot是每句的槽位数，不是总共5个参数向量。
- 模板 `a photo of a X view person with X X X X .`，视角槽初始化为aerial/ground词向量，共享槽初始化标准差0.02。
- 通过可训练的CLIP `visual.proj` 把768维特征投影到512维图文空间；温度使用原CLIP的exp(logit_scale)，固定不训练。
- A-before→aerial；A-after→ground；G-before/after→ground。四项各自按组求平均，再**相加×5**，不除以4。空组贡献0。
- 不重放before/after的DropPath随机状态，保留参考行为。因此训练中的margin差不应描述为严格只由Trajectory导致的反事实差值。
- VTC梯度进入共享主干、视觉投影、prompt和开启分支的Trajectory。before分支关闭Trajectory，其梯度仍更新主干和投影。

这里的“原样”指参考VTC目标、梯度路径与prompt语义；不是复现旧参考仓库整套运行环境。继续使用我们的Trajectory精度/公式、初始化权重、benchmark=False、采样器和训练器。文本模块初始化使用独立保存/恢复的CPU随机状态，避免额外文本初始化改变已有视觉随机序列；额外训练前向本身仍消耗随机数，所以不能承诺full与only的后续随机轨迹逐步相同。

## 3. 固定设置

| 设置 | 数值 |
|---|---|
| 初始化 | 原始CLIP ViT-B/16，不从已完成Trajectory checkpoint继续训练 |
| 输入与归一化 | 256×128；CLIP native mean/std |
| Trajectory | 11×129×768=1,089,792 gain参数，零初始化；beta=1 |
| 数据与batch | WHU-MARS-1000；PKM P16 K4；logical64，三模态主前向192，额外RGB before64 |
| 优化器 | Adam，weight decay=1e-4，AMP，梯度全局范数裁剪1 |
| 学习率 | 主干及base.clip_proj=5e-6；分类头/BN/prompt=3.5e-4；gain=3.5e-4 |
| 调度与轮次 | warmup100updates + cosine，60epoch，seed1234 |
| 视角ID | 数据集读入后零基camera IDs，aerial=[5,6]，对应文件名c6/c7 |
| VTC权重 | 5×四组CE求和，RGB-only |
| 检索 | 768维；L2；METRIC=sysu，排除全部同摄像头gallery；full ranking，无reranking |

`AERIAL_CAMS=[5,6]` 同时用于full监督和已有视角诊断；不会改变总体SYSU过滤规则。将输出模态对、A→G/G→A/G→G诊断；没有有效query的A→A保持undefined，不记为0分。

## 7. 输出与评估失败后的独立重试

每组输出目录：

```text
A_trajectory_direct_full/ 或 A_trajectory_full/
├── train_stdout.log
├── train_log_*.txt
├── config.yml
├── runtime.txt
├── pip_freeze.txt
├── nvidia_smi.txt
├── transformer_60.pth
├── eval_epoch60_postbn/eval_stdout.log
└── eval_epoch60_prebn/eval_stdout.log
```

config.yml为输入配置副本，启动时绝对路径覆盖后的完整配置以train/eval日志的resolved config为准。

如果只是复评失败，**不要重启整个训练脚本**。以下命令只复评direct full的post/pre，并写入新的retry1目录：

```bash
cd /mnt/cache/wanghanzhi/XK/WHU-Baseline
set -euo pipefail
export CUDA_VISIBLE_DEVICES=0 WORLD_SIZE=1 PYTHONUNBUFFERED=1
CONFIG=/mnt/cache/wanghanzhi/XK/WHU-Baseline/configs/A_trajectory_direct_full.yml
OUTPUT=/mnt/cache/wanghanzhi/XK/WHU-Baseline_runs/A_trajectory_direct_full
for NECK in after before; do
  if [ "$NECK" = after ]; then EVAL="$OUTPUT/eval_epoch60_postbn_retry1"; else EVAL="$OUTPUT/eval_epoch60_prebn_retry1"; fi
  mkdir -p "$EVAL"
  /mnt/cache/wanghanzhi/envs/whu_mars/bin/python3 test.py --config_file "$CONFIG" \
    MODEL.PRETRAIN_PATH /mnt/cache/wanghanzhi/Datasets/ViT-B-16.pt \
    MODEL.FULL.TEXT_CLIP_PATH /mnt/cache/wanghanzhi/Datasets/ViT-B-16.pt \
    DATASETS.ROOT_DIR /mnt/cache/wanghanzhi/Datasets \
    TEST.WEIGHT "$OUTPUT/transformer_60.pth" TEST.NECK_FEAT "$NECK" \
    OUTPUT_DIR "$EVAL" 2>&1 | tee "$EVAL/eval_stdout.log"
done
```

bounded复评时，将上面已定义的CONFIG改为`/mnt/cache/wanghanzhi/XK/WHU-Baseline/configs/A_trajectory_full.yml`，OUTPUT改为`/mnt/cache/wanghanzhi/XK/WHU-Baseline_runs/A_trajectory_full`。如果retry1已存在请使用retry2等新目录，不覆盖失败证据。

full checkpoint须用对应full配置加载，only/full混用会报错；direct/bounded仍由checkpoint里的spec检查。正常full加载应显示315/316项，唯一跳过classifier。评估时为简化一致加载仍构建文本模块，但不执行文本前向。

## 8. 监控解释与对照边界

- 保留原velocity、acceleration、correction/input、有效gain均值/最大值、未裁剪gain梯度范数和AMP累计跳步监控。
- 新增Full loss及乘权重值、RGB中航拍数量、四格accuracy、四格margin、push、drift。loss是截至打印点的epoch累计均值，accuracy/margin等是当前采样batch值，不要混用。
- 只有某组样本存在时该组accuracy/margin才有解释意义；n_aerial=0或n_aerial=n_total时，空组返回0用于计算，不代表准确率为0或机制失败。
- epoch结束新增精确打印该轮batch数和累计AMP跳步；旧`Optimizer updates`一行仍是遍历batch数，成功更新总数需从累计batch减去累计AMP跳步。
- 四格accuracy高和push为正仅证明该训练目标被满足，不能单独证明身份检索增益。地面保持ground类别不等于特征完全不动。

已有only实验来自AutoDL，本轮full来自商汤。**环境都叫whu_mars不等于包版本/硬件后端完全一致**。启动器会记录runtime和pip freeze；应与AutoDL torch2.2.2+cu121、torchvision0.17.2+cu121、timm1.0.27等实际文件核对。若环境不同，先视为探索性增量对照，正式归因需统一运行环境或补商汤同版本only控制；不要仅凭环境名称宣称严格单变量。

两组均从原始CLIP独立训练，额外VTC引入可学习prompt与额外前向，其收益解释为“加入参考监督整套训练机制”的效果。原样VTC不保证增加效果，也不能替代同监督下的执行器对照。
