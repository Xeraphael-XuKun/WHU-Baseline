# cuDNN benchmark 最小对照实验

日期：2026-09-22

## 1. 实验问题

老师历史 `train.py` 使用：

```python
torch.backends.cudnn.deterministic = True
torch.backends.cudnn.benchmark = True
```

原 A 使用：

```python
torch.backends.cudnn.deterministic = True
torch.backends.cudnn.benchmark = False
```

两次历史运行均配置 `SEED=1234`，并使用相同 WHU-MARS 配方。本对照只检验：

1. 原 A 在当前环境、同 seed 下能否稳定重复；
2. 将 `cudnn.benchmark` 改为 `True` 后，结果是否向老师历史结果移动。

## 2. 固定条件

两组共同固定：

- 单卡 A800-80GB；
- `CUDA_VISIBLE_DEVICES=0`、`WORLD_SIZE=1`；
- Python：`/mnt/cache/wanghanzhi/envs/whu_mars/bin/python3`；
- 数据：`/mnt/cache/wanghanzhi/Datasets/WHU-MARS`；
- 预训练权重：`/mnt/cache/wanghanzhi/Datasets/ViT-B-16.pt`；
- raw CLIP ViT-B/16；
- 原始 PKM，K=4，P=16；
- 逻辑 batch 64，实际三模态图片 batch 192；
- CE + soft-margin triplet；
- Adam，head LR `3.5e-4`，backbone LR `5e-6`；
- 100-update warmup、per-update cosine；
- 60 epochs，固定使用 epoch-60 checkpoint；
- `SEED=1234`；
- `R1_mAP_eval(metric=sysu, FEAT_NORM=yes)`；
- 训练结束后从磁盘重新加载 checkpoint 统一复评。

## 3. 两组实验

| 任务 | 配置 | `CUDNN_BENCHMARK` | 输出目录 |
|---|---|---:|---|
| D | `configs/D_A_repeat_benchmark_false.yml` | False | `/mnt/cache/wanghanzhi/XK/WHU-Baseline_runs/D_A_repeat_benchmark_false` |
| E | `configs/E_A_benchmark_true.yml` | True | `/mnt/cache/wanghanzhi/XK/WHU-Baseline_runs/E_A_benchmark_true` |

`CUDNN_BENCHMARK=False`；E相对D只改变
`CUDNN_BENCHMARK=True`和输出目录。

## 4. 服务器启动命令

平台创建两个独立单卡任务，按D、E顺序串行调度。

### 任务D：原A同设置重复

```bash
bash /mnt/cache/wanghanzhi/XK/WHU-Baseline/server/run_D_A_repeat_benchmark_false_a800.sh
```

### 任务E：老师benchmark设置

```bash
bash /mnt/cache/wanghanzhi/XK/WHU-Baseline/server/run_E_A_benchmark_true_a800.sh
```

两个脚本都会拒绝复用非空输出目录，避免覆盖旧结果。

## 5. 判读规则

以独立 `eval_epoch60/eval_stdout.log` 为统一主结果，同时保留训练进程在
epoch 60 输出的指标，用于观察 `benchmark=True` 是否影响同一进程内评测。

| 观察 | 解释 |
|---|---|
| D接近或复现A，E接近老师 | 支持cuDNN benchmark是主要差异来源 |
| D接近A，E仍接近A | benchmark不是主要原因，应继续检查历史环境或其他源码状态 |
| D与A已有明显差异 | 当前训练仍存在未控制的运行间波动，不能单独归因benchmark |
| D和E均稳定，但都不接近老师 | 更可能存在老师历史环境、依赖、数据或其他源码差异 |

当前只有一次A和一次老师历史运行，不预设数值阈值，也不把任一单次更高结果
解释为设置具有系统性性能优势。先报告A、D、E的逐epoch曲线、epoch-60统一复评
及九个模态对结果，再决定是否需要多seed实验。

## 6. 实现边界

- `config/defaults.py`新增`SOLVER.CUDNN_BENCHMARK=False`；
- `train.py`从配置读取该字段；
- A/B/C未显式设置该字段，因此继续使用False，行为不变；
- 不修改sampler、数据增强、loss、优化器、scheduler、模型或评测器；
- 不覆盖A/B/C已有输出。
