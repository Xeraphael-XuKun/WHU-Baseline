# E60、F60、G60 环境与 cuDNN 完整对照实验及服务器启动手册

## 1. 目的与代码边界

本实验将此前只运行 10 轮的 E10、F10、G10 扩展为从头完整训练 60 轮。实验代码从历史提交 `5378a466762f9a9553192ab75e28fde10d367f64` 建立独立分支，不使用已经过大规模清理和方法开发的 `70cf7cb`。

服务器保留当前目录 `/mnt/cache/wanghanzhi/XK/WHU-Baseline` 不动，新建独立 worktree：

```text
/mnt/cache/wanghanzhi/XK/WHU-Baseline-env-cudnn-e60
```

此前的 `transformer_10.pth` 只包含模型参数，不能恢复 optimizer、scheduler、AMP scaler 和随机数状态。因此三组均从 `ViT-B-16.pt` 重新开始，不从 epoch 10 续训。

## 2. 实验矩阵

| 组别 | Python 解释器 | CUDNN_BENCHMARK | SEED | MAX_EPOCHS | STOP_AFTER_EPOCH |
|---|---|---:|---:|---:|---:|
| E60 | `/mnt/cache/wanghanzhi/envs/whu_mars/bin/python3` | True | 1234 | 60 | 0 |
| F60 | `/mnt/cache/wanghanzhi/envs/llmpar/bin/python3` | True | 1234 | 60 | 0 |
| G60 | `/mnt/cache/wanghanzhi/envs/llmpar/bin/python3` | False | 1234 | 60 | 0 |

F60、G60 使用 `llmpar` 仅用于补全既有环境诊断矩阵，不作为后续正式 baseline 的推荐环境。该环境历史上存在 torch 2.4.1+cu121 与 torchvision 0.13.1 不配套以及 `libtorch_cuda_cu.so` 警告；两组必须使用同一未修改环境，不能只修复其中一组。

三组共同设置包括：逻辑训练 batch 64、实际图片 batch 192、`CHECKPOINT_PERIOD=10`、`EVAL_PERIOD=10`、`TEST.IMS_PER_BATCH=1024`、`TEST.NECK_FEAT=before`、`TEST.FEAT_NORM=yes`、`TEST.METRIC=sysu`。

## 3. 服务器创建独立 worktree

```bash
cd /mnt/cache/wanghanzhi/XK/WHU-Baseline
git fetch origin codex/env-cudnn-e60

git worktree add --detach \
  /mnt/cache/wanghanzhi/XK/WHU-Baseline-env-cudnn-e60 \
  origin/codex/env-cudnn-e60

git -C /mnt/cache/wanghanzhi/XK/WHU-Baseline-env-cudnn-e60 status --short
git -C /mnt/cache/wanghanzhi/XK/WHU-Baseline-env-cudnn-e60 rev-parse HEAD
```

`status --short` 必须为空。不要在原有 `WHU-Baseline` 目录执行 checkout、reset 或 pull 来替换当前版本。

## 4. 启动前预检

在正式任务之外先运行一次：

```bash
bash /mnt/cache/wanghanzhi/XK/WHU-Baseline-env-cudnn-e60/server/preflight_env_cudnn_e60_a800.sh
```

只有出现以下结束标记才可提交三个正式任务：

```text
EFG60_A800_PREFLIGHT_OK
```

预检会核对两套解释器的核心版本、数据集、CLIP 权重、Git 工作区和单卡 CUDA 反向传播。`llmpar` 的 `pip check` 非零属于已知环境诊断信息，但核心版本断言或 CUDA 检查失败会直接阻止预检通过。

## 5. 三个独立任务的启动命令

在商汤任务界面一次创建三个任务并按顺序排队。每个任务只填写对应的一条命令，均为单卡前台执行；不要使用 `nohup`、`&` 或 `torchrun`。

## 6. 输出目录与完成条件

```text
/mnt/cache/wanghanzhi/XK/WHU-Baseline_runs/diagnostic_e60/E60_whu_benchmark_true
/mnt/cache/wanghanzhi/XK/WHU-Baseline_runs/diagnostic_e60/F60_llmpar_benchmark_true

```

启动脚本拒绝复用非空输出目录。每组完成后必须同时满足：

1. 存在非空 `transformer_60.pth`；
2. `train_stdout.log` 正常完成 60 轮；
3. `eval_epoch60/eval_stdout.log` 完成磁盘重载复评；
4. 日志末尾出现该组的 `*_TRAIN_AND_DISK_RELOAD_EVAL_OK`；
5. 输出目录中保留 `git_commit.txt`、`pip_freeze.txt` 和 `nvidia_smi.txt`。

现有 A baseline 可作为 `whu_mars + CUDNN_BENCHMARK=False` 的 60 轮参照。若后续要求四格全部来自同一提交和同一批次算力，再额外补跑 D60。
