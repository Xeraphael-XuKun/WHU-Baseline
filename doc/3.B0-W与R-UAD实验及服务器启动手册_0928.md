# B0-W 与 R-UAD 实验及服务器启动手册

## 1. 实验目的

本轮只运行以下两组实验，暂不运行 CLIP + ProCA 与 CLIP + GPD 单模块消融：

| 组别 | 基础损失 | 新增模块 | 作用 |
|---|---|---|---|
| B0-W | CE + WRT | 无 | 检验 A 中 Triplet 换成 WRT 的单变量影响，并作为 UAD 的直接基础对照 |
| R-UAD | CE + WRT | `0.01 × ProCA + GPD` | 检验完整 UAD 损失组合加入锁定 CLIP baseline 后的效果 |

代码中的 `PCA` / `pca` 对应论文所称 ProCA。R-UAD 是将 UAD 损失模块接入当前锁定的 CLIP baseline，不是对原始 ViT/SGD/120 epoch UAD 配方的复现。

## 2. 固定设置

两组均继承 `A_baseline_candidate.yml` 的正式 baseline 配方：

- CLIP ViT-B/16 visual encoder；
- CLIP native normalization；
- PKM，`K=4`，逻辑 batch 64，实际图像 batch 192；
- Adam，训练 60 epoch，seed 1234；
- 单卡 `CUDA_VISIBLE_DEVICES=0`、`WORLD_SIZE=1`；
- 固定使用 epoch-60 checkpoint；
- 768D pre-BN，`TEST.NECK_FEAT=before`；
- `metric=sysu`、`FEAT_NORM=yes`。

配置间的完整差异由 `tests/test_b0_wrt_r_uad.py` 锁定：

- A → B0-W：只改变 `MODEL.METRIC_LOSS_TYPE: triplet → wrt`，另有独立输出目录；
- B0-W → R-UAD：只改变 `MODEL.PCA_LOSS_WEIGHT: 0 → 0.01` 和 `SOLVER.LOSS_TYPE: base → base+pca+gpd`，另有独立输出目录；
- `GPD_MOMENTUM=0.2` 与项目默认值一致，因此不会构成 B0-W 与 R-UAD 之外的隐藏配方差异。

## 4. 独立启动命令

B0-W：

```bash
bash /mnt/cache/wanghanzhi/XK/WHU-Baseline/server/run_B0_WRT_a800.sh
```

R-UAD：

```bash
bash /mnt/cache/wanghanzhi/XK/WHU-Baseline/server/run_R_UAD_a800.sh
```

两组分别写入：

```text
/mnt/cache/wanghanzhi/XK/WHU-Baseline_runs/B0-W
/mnt/cache/wanghanzhi/XK/WHU-Baseline_runs/R-UAD
```

启动脚本会拒绝复用非空输出目录，训练成功后检查 `transformer_60.pth`，再从磁盘加载该固定 checkpoint 完成一次独立复评。原 A/B/C 输出不会被覆盖。

## 5. 结果比较关系

- A vs B0-W：回答普通 Triplet 与 WRT 在当前 CLIP baseline 中的差异；
- B0-W vs R-UAD：回答完整 ProCA + GPD 组合的增益；
- A vs R-UAD：只能作为总体变化参考，不能把差异全部归因于 UAD，因为其中同时包含 Triplet → WRT。
