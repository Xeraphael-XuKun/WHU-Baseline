# 7. AutoDL单卡A800实验手册（2026-09-29）

## 1. 实验目标与执行顺序

本轮检验 **A baseline + Trajectory**，不启用VTC。
优先运行有界gain主方案；随后在同一AutoDL环境重跑A作为正式配对对照；直接gain为补充实验。
若只租一张GPU，三组依次运行。每个实验独立前台运行，单卡 `CUDA_VISIBLE_DEVICES=0`、
`WORLD_SIZE=1`，不使用DDP/torchrun。预检和完整训练是两条独立命令。

| 组别 | 配置 | Trajectory | 用途 |
|---|---|---|---|
| A control | configs/A_baseline_candidate.yml | 关闭 | AutoDL环境下的配对基线 |
| A + Trajectory | configs/A_trajectory.yml | beta=1；G=0.1*tanh(g/0.1) | 核心主方案 |
| A + Trajectory direct | configs/A_trajectory_direct.yml | beta=1；G=g | 有界约束补充对照 |

商汤历史A保留为参考，不能将跨平台环境差异直接归因于Trajectory。
三组均从原始CLIP初始化开始，不从历史A的第60轮权重续训。

## 3. 固定超参数与比较协议

| 项目 | 三组共同设置 |
|---|---|
| 主干 / 输入 | CLIP ViT-B/16 / 256×128 / CLIP native normalization |
| 采样 | 原PKM，P16 K4，RGB/IR/Thermal；逻辑batch64，实际192图 |
| 数据加载 | workers8；原独立增强设置 |
| 损失 | CE + soft-margin batch-hard Triplet；Triplet使用pre-BN |
| 优化器 | Adam；主干5e-6，BN/分类头3.5e-4，weight decay1e-4 |
| 新增gain | 零初始化，1,089,792参数，独立LR3.5e-4，weight decay1e-4 |
| 训练 | 60epochs；100updates warmup+cosine；seed1234 |
| 数值设置 | AMP默认scale，梯度裁剪1.0，deterministic=True，benchmark=False |
| 评测 | batch1024；pre-BN768；L2；sysu同相机过滤；无reranking |
| checkpoint | 固定transformer_60.pth；每10轮中间评测，不选测试集最佳轮次 |

Trajectory完整保留速度梯度，全模态/全视角共享；不改batch或引入梯度累积。
如果实际显存不足，先保留错误日志；不能仅降低Trajectory组batch再与原A作严格比较。
本地12图smoke通过不代表AutoDL上实际192图已通过。

## 4. 单独预检

在AutoDL终端直接执行：

```bash
mkdir -p /root/autodl-tmp/XK/WHU-Baseline_runs/autodl/preflight
set -o pipefail
bash /root/autodl-tmp/XK/WHU-Baseline/server/preflight_trajectory_autodl.sh 2>&1 | tee /root/autodl-tmp/XK/WHU-Baseline_runs/autodl/preflight/preflight_stdout.log
```

预检输出Python/torch/torchvision/timm/CUDA/cuDNN、GPU名称与显存，执行pip check、Trajectory
机制检查及真实数据/CLIP模型构建。最后应看到 `AUTODL_PREFLIGHT_OK`。
检查nvidia-smi确认租赁的确是计划使用的A800，且没有其他训练占用同卡。
预检不执行真实batch的反向传播；正式训练的首个正常iteration才是进一步启动证据。

先保留真实环境信息，不要直接 `pip install -r requirements.txt` 覆盖已有环境：requirements是
声明版本，不是当前AutoDL或历史商汤运行环境的实测记录。pip check失败或CUDA不可用时先解决具体错误。
可保存完整依赖记录：


保持终端连接；若使用已有tmux会话，在会话内前台执行相同命令。不要用nohup后台启动替代。

## 6. 启动、监控与完成判据

1. 启动后确认打印的是AutoDL配置与输出，TRAIN配置为60轮、逻辑batch64、单卡。
2. 看到正常 `Epoch[1] Iteration[50/...]`、有限loss，结合nvidia-smi确认进程和显存。
3. Trajectory应打印gain独立优化器组，形状(11,1,129,768)、峰值LR0.00035。
   warmup阶段日志中的实际LR更小是正常现象。
4. 查看Trajectory的gradient、有效gain、correction/input、amp_skipped_total。
   初始修正为零符合零初始化；持续非有限梯度/跳步需排查，不能仅凭进程存活判断正常。
5. 训练成功应生成非空transformer_60.pth；还应等脚本完成独立复评。
   最终结果以eval_epoch60/eval_stdout.log为准，核对已加载当前组权重。

每组保留train_stdout.log、训练器日志、transformer_60.pth、eval_epoch60目录及环境记录。
固定轮次报告mAP、Rank-1/5/10，并观察分视角/模态结果。单种子结论是首轮结果，非稳定优越性证明。

## 7. 训练已完成、仅重新复评主方案

若训练已产生完整第60轮权重，但随后复评失败，不需要重训。修复具体问题后执行：

```bash
cd /root/autodl-tmp/XK/WHU-Baseline
export CUDA_VISIBLE_DEVICES=0
export WORLD_SIZE=1
export PYTHONUNBUFFERED=1
set -o pipefail
mkdir -p /root/autodl-tmp/XK/WHU-Baseline_runs/autodl/A_trajectory/eval_epoch60_retry1
/root/autodl-tmp/envs/whu_mars/bin/python3 test.py \
  --config_file /root/autodl-tmp/XK/WHU-Baseline/configs/A_trajectory.yml \
  MODEL.PRETRAIN_PATH /root/autodl-tmp/ViT-B-16.pt \
  DATASETS.ROOT_DIR /root/autodl-tmp \
  TEST.WEIGHT /root/autodl-tmp/XK/WHU-Baseline_runs/autodl/A_trajectory/transformer_60.pth \
  OUTPUT_DIR /root/autodl-tmp/XK/WHU-Baseline_runs/autodl/A_trajectory/eval_epoch60_retry1 \
  2>&1 | tee /root/autodl-tmp/XK/WHU-Baseline_runs/autodl/A_trajectory/eval_epoch60_retry1/eval_stdout.log
```

其他两组必须同步更换对应配置、权重和输出路径；主方案与direct配置不可混用。
retry目录若已存在，请递增编号，保留失败日志。

## 8. 中断与证据边界

正式脚本拒绝非空输出目录。失败重跑时保留旧目录和日志，将对应脚本OUTPUT改成新的绝对路径，
例如 `/root/autodl-tmp/XK/WHU-Baseline_runs/autodl/A_trajectory_retry1`，其余设置不变。
当前保存的是模型state_dict，训练入口没有恢复optimizer/scheduler/GradScaler的完整resume机制；
不能把PRETRAIN_CHOICE=self或加载中间模型说成无缝续训。默认仅第60轮保存正式checkpoint。

本手册及脚本在本地核对路径与语法，不代表已验证AutoDL环境或启动了远程实验。
