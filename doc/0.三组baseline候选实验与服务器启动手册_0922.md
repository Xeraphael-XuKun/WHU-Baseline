## 2. 实验组

| 顺序 | 任务名 | 对应旧代号 | Sampler | P_AG | P_G | K | 逻辑 batch | 实际图片 batch | unique PID |
|---:|---|---|---|---:|---:|---:|---:|---:|---:|
| 1 | `A_baseline_candidate` | T0 / 老师复现方案 | 普通 PKM | - | - | 4 | 64 | 192 | 16 |
| 2 | `B_baseline_candidate` | F192 / Stratified-192 | 分层 PKM | 8 | 8 | 4 | 64 | 192 | 16 |
| 3 | `C_fused_baseline_candidate` | F96 / Stratified-96 | 分层 PKM | 8 | 8 | 2 | 32 | 96 | 16 |

按当前 WHU-MARS-1000 数据和 sampler 声明长度，A/B 的 scheduler 分母均为
`469 step/epoch`，C 为 `952 step/epoch`。老师原始 A sampler 的 `__len__` 与
实际迭代器长度不一致：固定 seed 的审计显示实际约为 `455–461` updates/epoch；
B 实际为469，C实际为952。该历史行为保留在A中，训练日志会同时记录
`Optimizer updates: actual/scheduler denominator`。

B/C 会将估算的 epoch 样本数向上补齐到完整 batch，因此每一个 batch（包括
最后一个）都严格满足 `P_AG=8、P_G=8、unique PID=16`；这不会改变上述
scheduler step 数。

### A：老师方案复现候选

- 使用老师原始 `PKMSampler`，不改其抽样算法。
- 每个逻辑样本返回 RGB、IR、Thermal 三张图。
- `64 = 16 PID × K4` 个逻辑样本，实际前向 `64 × 3 = 192` 张图。
- 参考目标：mAP `11.99`、Rank-1 `31.10`、Rank-5 `48.57`、Rank-10 `56.69`。
- 若新结果低于老师约 `1.0 mAP` 或 `2.0 Rank-1` 以上，先检查实现和环境，
  不直接解释为随机波动。

### B：主 baseline 候选

只将 A 的普通 PKM 替换为 WHU 视角分层 PKM：

```text
P_AG=8, P_G=8, M=3, K=4
actual batch=192, unique PID=16
```

每个 cross-view PID 在每种模态中抽取 `2 Ground + 2 Aerial`；每个
Ground-only PID 在每种模态中抽取 `4 Ground`。因此每批 Ground:Aerial 为
`144:48 = 3:1`，同时保留 Ground-only 身份。

`B − A`主要回答：在相同 `K4/192`、模型和名义优化设置下，包含身份/视角分布
与有效 epoch 长度在内的分层 sampler recipe，整体是否优于老师普通 PKM。

### C：K2/96 对照

与 B 使用相同分层逻辑，但每个 PID 每种模态只抽取两张图：cross-view PID
为 `1 Ground + 1 Aerial`，Ground-only PID 为 `2 Ground`。

`B − C`回答的是 `K2/96 → K4/192` 整套 batch construction 的影响；它同时
改变 triplet 候选池和每 epoch optimizer steps，不能写成“仅 K 的独立贡献”。

## 3. 三组共同设置

- OpenAI CLIP ViT-B/16 raw checkpoint。
- 输入 `256×128`，CLIP native mean/std。
- 单一 768D pre-projection CLS；一个 BNNeck/classifier。
- CE，无 label smoothing；soft-margin batch-hard triplet。
- 推理使用 768D pre-BN 特征。
- Adam；pretrained LR=`5e-6`，new head LR=`3.5e-4`。
- weight decay=`1e-4`，`BIAS_LR_FACTOR=1`。
- 60 epochs，100-update linear warmup，per-update cosine，min factor=`0.002`。
- 12层线性 DropPath `0→0.1`。
- AMP unscale 后全局 gradient clip=`1.0`。
- seed=`1234`，单卡，`WORLD_SIZE=1`。
- 固定 epoch-60 checkpoint，不按 test peak 选择权重。
- `R1_mAP_eval(metric='sysu', FEAT_NORM='yes')`，full ranking，无 reranking。

显式关闭：`CE_SPLIT_VIEW`、`CE_SPLIT_MODALITY`、`MOD_DELTA`、`TEXT_ALIGN`、
ProCA、GPD、twin loss、TNCE 和其他非 baseline loss。

## 6. 一次性创建三个串行任务

在算力平台中同时创建三个独立任务，设置顺序为 A → B → C。每个任务只执行
自己的前台脚本。

任务1：

```bash
bash /mnt/cache/wanghanzhi/XK/WHU-Baseline/server/run_A_baseline_candidate_a800.sh
```

任务2：

```bash
bash /mnt/cache/wanghanzhi/XK/WHU-Baseline/server/run_B_baseline_candidate_a800.sh
```

任务3：

```bash
bash /mnt/cache/wanghanzhi/XK/WHU-Baseline/server/run_C_fused_baseline_candidate_a800.sh
```

三个脚本都将：

1. 拒绝复用非空输出目录；
2. 前台执行完整训练；
3. 检查 `transformer_60.pth` 非空；
4. 从磁盘重新加载 epoch-60 checkpoint；
5. 将复评日志写入各自的 `eval_epoch60/`。

三组不会加载彼此的 checkpoint，也不会共享日志或输出目录。平台串行调度只控制
启动顺序，不改变实验独立性。

## 7. 结果解释与后续门槛

- A 是老师当前有效快照的复现候选。
- B 与 A 是主要 sampler-recipe comparison；由于老师 sampler 的声明长度与实际
  迭代长度不一致，不能把差值收窄解释为“仅视角比例”的独立贡献。
- B 与 C 是 batch construction 对比，不是单变量 K 消融。
- 以固定 epoch-60 mAP 为首要指标，同时报告 Rank-1/5/10。
- 若前两名差距小于约 `0.3 mAP`，单 seed 不足以确定最终 baseline；只给前两名
  各补两个 seed。
- 获胜配置锁定后，再进行非 baseline 模块清理和清理前后等价性验证。
- 如果清理不能保持等价，则清理后的版本必须重新训练，不能直接继承今晚结果。
